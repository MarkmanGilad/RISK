# Actions

Reference for every action type in the game, defined in
[`risk/game/actions.py`](../risk/game/actions.py).

All actions are **immutable, frozen dataclasses**. Each one:

- has a `phase: ClassVar[Phase]` saying which game phase it belongs to
- only validates its own **shape** in `__post_init__` (field types, ranges,
  non-empty strings) — it does **not** check legality against the board
  (ownership, adjacency, budget, army counts). That's `Environment`'s job
  (`Environment.step(action)` raises `ValueError` for anything illegal).
- has a `to_dict()` for logging/replay/RL trajectories.

`ActionCodec.from_dict(data)` (also in `actions.py`) is the inverse of
`to_dict()` — rebuilds the right dataclass from its dict form, keyed by a
`"type"` string.

`Environment.legal_actions()` ([`risk/game/environment.py`](../risk/game/environment.py))
enumerates the legal instances of these for the *current* phase — see the
"Generated by `legal_actions()`" note on each action below.

## `ReinforcementAction`

Place armies on your own territories at the start of your turn.

```python
ReinforcementAction(placements={"Alaska": 3, "Alberta": 2})
```

- `placements` — `{territory_id: army_count}`. Can spread armies across any
  number of your own territories in one action.
- **Validates:** non-empty dict, every count is a non-negative int, and the
  total isn't zero (an all-zero placement is meaningless).
- **Environment also checks** (at `step()` time): every territory is owned
  by the current player, and the total does **not exceed**
  `state.reinforcement_budget` (it no longer has to match exactly).
- **Reinforcement is multi-step.** Placing less than the full budget keeps
  the player in `REINFORCE_PLACE` (budget decremented, not zeroed) so they
  can place the rest in a later action; the phase only advances to `ATTACK`
  once the budget reaches `0`. Placing the whole budget in one action (the
  human UI's only mode — see [How to play](../README.md#controls-during-a-match))
  still ends the phase in a single step exactly as before; multi-step is
  optional, not required.
- **Generated by `legal_actions()`:** a small **bucketed** set per owned
  territory — `1`, `budget // 2`, and `budget` (deduplicated, so e.g. a
  budget of 1 yields only one legal action). This stays bounded by
  `O(owned territories)` regardless of how large the budget gets — it
  deliberately does **not** enumerate every integer amount, which would
  scale with army count instead of board size. Any other split is still
  reachable over a few actions; agents that want a specific amount this
  step can construct their own `ReinforcementAction` directly.

## `TradeInAction`

Cash in a 3-card set from your hand during `TRADE_IN`, adding its value to
your reinforcement budget.

```python
TradeInAction(card_indices=(0, 2, 4))
```

- `card_indices` — 3 distinct, non-negative positions into
  `state.hands[current_player]`.
- **Validates:** exactly 3 indices, all ints, all distinct.
- **Environment also checks:** indices are within the hand's current
  length, and the 3 cards form a valid set (3-of-a-kind or one-of-each,
  wilds substitute for anything — see `CardRules.is_valid_set`).
- **Generated by `legal_actions()`:** every valid 3-card combination
  currently in the player's hand. If the hand has reached `MAX_CARDS_IN_HAND`
  (5), `legal_actions()` returns **only** trade-in actions (no
  `SkipTradeAction`) — you must trade down before moving on. Trading
  doesn't end the phase by itself — `TRADE_IN` stays active (you can trade
  another set if you have one) until a `SkipTradeAction` advances to
  `REINFORCE_PLACE`. If there are **no** valid sets, `Environment`
  auto-skips `TRADE_IN` to `REINFORCE_PLACE` (no skip prompt/action needed).
- **Ordinary conquest draw is never forced mid-attack:** the one card drawn
  on a player's first conquest of their turn is kept even if it brings the
  hand to `MAX_CARDS_IN_HAND` — the attack/occupy/fortify flow continues
  normally. That player is only forced to trade at the *start of their next
  turn* (`TRADE_IN`, mandatory once hand `>= MAX_CARDS_IN_HAND`), same as
  reaching the limit any other way.
- **Mid-attack forced trade-in — elimination only:** eliminating an opponent
  transfers their hand to you immediately (`Environment._apply_attack`); if
  that (and only that) pushes your hand to `MAX_CARDS_IN_HAND` or beyond,
  the environment routes you into `TRADE_IN` *before* the parked
  `OccupyAction` instead of straight to `OCCUPY`. Trading is mandatory while
  the hand stays at or above `MAX_CARDS_IN_HAND` — for a large inherited
  hand (e.g. 9 cards) this may take several consecutive `TradeInAction`s
  (9 -> 6 -> 3) — and each set's value accumulates in
  `reinforcement_budget`. Once the hand is below the limit (via trades or a
  now-legal `SkipTradeAction`), the environment advances to
  `REINFORCE_PLACE` so the accumulated value can be placed — same as a
  normal `TRADE_IN` — except once that budget reaches zero, `Environment`
  detects `state.pending_attack is not None` and resumes `OCCUPY` instead of
  starting a fresh `ATTACK` phase, without resetting `conquered_this_turn`.
  A hand can reach up to `MAX_TRANSIENT_HAND_SIZE` (`risk/constants.py`)
  cards in this window — `TradeInHead`'s card-slot embedding
  (`Docs/NetworkArchitectures.md`) is sized for that, not for
  `MAX_CARDS_IN_HAND`.
- **Territory bonus:** for each non-wild card in the set whose
  `territory_id` is currently occupied by the trading player,
  `CARD_TERRITORY_BONUS_ARMIES` (2) armies are placed directly on that
  territory immediately — on top of, and independent from, the set's
  reinforcement-budget value.

## `SkipTradeAction`

End your `TRADE_IN` phase voluntarily (no more trades this turn) and
advance to `REINFORCE_PLACE`.

```python
SkipTradeAction()
```

- No fields, no validation needed — same shape as `StopAttackAction`.
- **Generated by `legal_actions()`:** included alongside enumerated
  `TradeInAction`s during `TRADE_IN`, **unless** the hand has reached
  `MAX_CARDS_IN_HAND` (mandatory trading), or there are no valid sets
  (the environment auto-skips directly to `REINFORCE_PLACE`).

## `AttackAction`

Attack an adjacent enemy/neutral territory.

```python
AttackAction(from_territory="Alaska", to_territory="Alberta", dice=3)
```

- `from_territory` / `to_territory` — non-empty, distinct territory ids.
- `dice` — int in `1..MAX_ATTACK_DICE` (1–3).
- **Validates:** the two fields above, plus `dice` range.
- **Environment also checks:** you own `from_territory` and don't own
  `to_territory`, they're adjacent, `from_territory` has ≥2 armies, and
  `dice <= min(MAX_ATTACK_DICE, armies_from - 1)`.
- **What happens:** both sides roll (`dice` for the attacker, up to
  `MAX_DEFEND_DICE` (2) capped by the defender's armies); highest dice are
  compared pairwise, ties favor the defender. If the defender's armies hit
  zero, the territory is conquered and the environment forces
  `Phase.OCCUPY` — the next action must be an `OccupyAction` — **unless**
  conquering eliminated the defender and the inherited cards push your hand
  to `MAX_CARDS_IN_HAND` or beyond, in which case it forces `Phase.TRADE_IN`
  first (see `TradeInAction`'s "Mid-attack forced trade-in — elimination
  only" above; an ordinary conquest draw alone never forces this).
- **Generated by `legal_actions()`:** every `(from, to, dice)` combination
  where `from` is owned with ≥2 armies, `to` is an adjacent non-owned
  territory, and `dice` ranges over `1..min(MAX_ATTACK_DICE, armies_from-1)`.

## `StopAttackAction`

End your attack phase voluntarily (no more attacks this turn) and advance to
`FORTIFY`.

```python
StopAttackAction()
```

- No fields, no validation needed.
- **Generated by `legal_actions()`:** always included alongside the
  enumerated `AttackAction`s during `ATTACK` — you can stop at any time.

## `OccupyAction`

Move armies from the attacker into a territory you just conquered. Only
legal immediately after a conquest, while `Phase.OCCUPY` is active.

```python
OccupyAction(count=5)
```

- `count` — int, must be ≥1.
- **Validates:** type and the `>= 1` floor.
- **Environment also checks:** `count` is within
  `[lo, hi]` where `hi = armies_from - 1` (must leave ≥1 army behind) and
  `lo = max(1, min(attacker_dice, hi))` (must move at least as many as you
  attacked with, when possible).
- **Generated by `legal_actions()`:** every integer count in that `[lo, hi]`
  range.

## `FortifyAction`

Move armies between two of your own territories once per turn (or skip).

```python
FortifyAction(from_territory="Alaska", to_territory="Alberta", count=4)
FortifyAction(from_territory=None, to_territory=None, count=0)   # skip
```

- `from_territory` / `to_territory` — `Optional[str]`; required (non-empty,
  distinct) only when `count > 0`.
- `count` — int ≥ 0. **`count == 0` means "skip fortify"** — there's no
  separate "skip" action class, `is_skip` is just a property
  (`count == 0`) on this same class.
- **Validates:** `count >= 0`; if `count > 0`, both territory fields are
  required and distinct.
- **Environment also checks:** (when not skipping) you own both
  territories, `count < armies_from` (must leave ≥1 behind), and the two
  territories are connected through a chain of territories you own
  (BFS, see `Environment._connected_through_owned`).
- **Either way**, applying a `FortifyAction` ends your turn and advances to
  the next player's `TRADE_IN`.
- **Generated by `legal_actions()`:** the skip action, plus for each
  reachable owned source-destination pair (source with ≥2 armies, every
  other owned territory reachable through your territory), the deduplicated
  transfer amounts `1`, `(1 + maximum) // 2`, and `maximum`, where
  `maximum = armies_from - 1`. A directly submitted count anywhere from `1`
  through `maximum` remains valid — `legal_actions()` only enumerates this
  bounded 1/middle/maximum set for tractability, not every integer amount.

## Round-tripping

```python
from risk.game.actions import ActionCodec, AttackAction

a = AttackAction(from_territory="Alaska", to_territory="Alberta", dice=2)
d = a.to_dict()                      # {"type": "attack", "from_territory": "Alaska", ...}
b = ActionCodec.from_dict(d)          # AttackAction(...) — equal to `a`
```

Useful for logging a game, replaying it, or serializing trajectories for
training.

## Representing actions for learning — `Q(s, a)`

**The problem.** Risk's legal action set is a different shape and size
every step (varies by phase, by how many territories you own, by hand
size, ...), so there's no fixed-size action vector to argmax over directly.
The fix: don't enumerate every theoretically possible action — score only
the legal actions `Environment.legal_actions()` already gives you for the
current state, and pick the highest-scoring one.

### Current representation: inject each candidate into the state graph

The implemented learning agents represent a territory-changing candidate by
building a separate graph from the same base state. `ActionGraphBuilder`
([ActionGraphBuilder.md](ActionGraphBuilder.md)) preserves the real `armies`
feature and writes the candidate's signed proposed movement into the base
graph's zero-filled `proposed_army_delta` feature: reinforcement writes `+n`
at its target, while occupy and fortify write `-n` at the source and `+n` at
the destination. An attack instead marks its directed edge with its selected
flag and normalized dice count. Stop/skip actions and trade-in actions return
an unmodified graph copy.

Thus the network scores one injected graph for each legal action; the action
object itself is still passed to `env.step(...)` after selection. Keeping the
base army count unchanged is important for the clean state/value graph, while
the signed-delta column exposes the action proposal to an action-scoring
stream. See [ActionGraphBuilder.md](ActionGraphBuilder.md) for the complete
stage-by-stage mapping and [GraphAdapter.md](GraphAdapter.md) for the node
feature layout.

### Internal action coordinates

`Action.dqn_index(...)` remains the common, torch-free mapping used by
`ActionGraphBuilder` to locate the affected node(s) or edge. It is also
available to `ActionEncoder` for code that needs a compact action tuple, but
the injected-graph learners do not feed that tuple into a separate action
head.

Every `Action` subclass encodes itself via
`Action.dqn_index(topology, state=None) -> tuple[int, int, int, int]`
([`risk/game/actions.py`](../risk/game/actions.py)) — plain Python, no
torch import in the game core. `risk.learning.action_encoder.ActionEncoder`
([`risk/learning/action_encoder.py`](../risk/learning/action_encoder.py))
batches those tuples into tensors:

```python
from risk.learning.action_encoder import ActionEncoder

encoder = ActionEncoder(env)
legal_actions, tensor = encoder()                  # tensor: [len(legal_actions), 4] long
# ... use `tensor` where a compact action representation is needed ...
env.step(legal_actions[i])                          # the winning action is already a real Action
```

`state` is required (not just `topology`) for `OccupyAction` specifically
— its `from`/`to` territories live on `state.pending_attack`, not on the
action itself. `ActionEncoder` holds the `env`, so it pulls
`env.topology`/`env.current_state()` automatically every call.

### The tuple: `(phase, t1, t2, n)`

Four integers per legal action:

| Field | Meaning |
|---|---|
| `phase` | `int(action.phase)` — the `Phase` value (`risk/game/phase.py`) this action belongs to; selects which head scores it — see below. `Phase` doubles as the DQN action-representation "stage" directly, no separate enum for it |
| `t1` | a territory index (`topology.index_of(...)`, 0..41) — or, for `TRADE_IN`, a card-hand-slot index, normally 0..4 but up to `MAX_TRANSIENT_HAND_SIZE - 1` during a mid-attack forced trade-in (see `TradeInAction` above) |
| `t2` | a second territory index, or card-hand-slot index — or `-1` (`Action.NONE_INDEX`, sentinel) if this stage doesn't use a second slot |
| `n` | dice count, army count, a third card-hand-slot index, or `0`/unused depending on stage — see table |

**5 decision stages** — every `Phase` value except `SETUP`/`GAME_OVER`,
which aren't agent decisions so no `Action` ever has those as its `phase`:

| `phase` | Action class(es) | `t1` | `t2` | `n` |
|---|---|---|---|---|
| 0 `TRADE_IN` | `TradeInAction`, `SkipTradeAction` | card-slot index (1st), or `-1` to skip | card-slot index (2nd), or `-1` to skip | card-slot index (3rd), or `0` to skip |
| 1 `REINFORCE_PLACE` | `ReinforcementAction` | territory to place on | `-1` | amount placed (`1` / `budget // 2` / `budget` — see note) |
| 2 `ATTACK` | `AttackAction`, `StopAttackAction` | `from` territory, or `-1` for stop | `to` territory, or `-1` for stop | `dice` (1–3), or `0` for stop |
| 3 `OCCUPY` | `OccupyAction` | pending attack's `from` territory | pending attack's `to` territory | `count` |
| 4 `FORTIFY` | `FortifyAction` | `from` territory, or `-1` for skip | `to` territory, or `-1` for skip | `count`, or `0` for skip |

`StopAttackAction`, `SkipTradeAction`, and "skip fortify" aren't separate
stages — they're just the sentinel (`-1, -1, 0`) action that's always
present alongside the real `AttackAction`/`TradeInAction`/`FortifyAction`
legal actions in stages 0/2/4 (except `TRADE_IN` when a trade is mandatory
— see `TradeInAction`'s "Generated by `legal_actions()`" note above),
exactly like `legal_actions()` always includes them alongside the
enumerated moves.

This is a direct, mechanical mapping from each legal `Action` object
(already produced by `legal_actions()`) to one `(phase, t1, t2, n)` tuple —
no information is invented, nothing needs decoding back, because the
action object itself is still what gets passed to `env.step(...)` once
chosen. For injected-graph learning, the tuple is an internal locator for
the perturbation, not a separate network input.

**Reinforcement note:** reinforcement is multi-step (see the
`ReinforcementAction` section above) and `legal_actions()` offers a
bucketed `n` per territory — `1`, `budget // 2`, `budget` (deduplicated) —
instead of every integer amount, so the legal-action count stays `O(owned
territories)` rather than scaling with army count. `n` is therefore a
real, meaningful choice every step, not a constant: the agent picks both
*where* and *how much*, and can return to `REINFORCE_PLACE` again next
step with whatever budget remains.

Only actions returned by `legal_actions()` are injected and scored, so illegal
moves are never represented as candidate graph rows and require no separate
mask tensor.
